# 使用说明

先运行 setup.cmd，再运行 start.cmd，在“网盘授权…”中完成自己的账号授权。

## 自动归档

先启动主程序，再添加项目。程序会创建“云空间”、Agent 说明和启动快捷方式。
拖入确定不再需要留在本地的普通文件，稳定 10 秒后自动处理。
依次完成上传、完整下载校验、本地记录持久化、云端索引上传与回读核对，才释放被锁定的同一本地原件。
任何必要校验失败都保留原件。跨盘拖放通常是复制，本程序只释放“云空间”里的副本。

关闭窗口会等待当前文件结束；没有后台系统服务，也没有自动开机启动。
“暂停自动上传”影响后续文件，正在处理的文件先完成。

## 本地数据

- 程序目录 `.state`：项目映射、队列、状态、轮换日志、整项目恢复报告。
- 项目目录“云空间”中的 `.云空间配置.json`、`.云端记录`：映射和恢复记录。
- “云空间恢复”：单文件恢复结果；整项目恢复到用户指定的位置。
- `%LOCALAPPDATA%/ProjectCloudSpace/credentials.dpapi`：当前 Windows 用户的加密授权。

前两类记录不是临时缓存。不要为腾空间随意删除；它们可能含私人项目名和路径，不能提交到公开仓库。
程序不会上传云空间根目录中的说明、配置、记录和专用启动快捷方式。

## 恢复单个文件

选择项目和归档记录，点击“恢复选中文件”。结果在该项目的“云空间恢复”目录。
保留原相对路径；已有不同内容的同名文件不会覆盖。完整下载并核对大小与 SHA-256 后才保留恢复结果。

## 批量队列与自动重试

可以一次拖入 34 个或更多文件；全部登记后逐个上传、完整下载校验，再释放原件。
文件稳定 10 秒才开始。网络类失败每个文件最多尝试 3 次（首次 + 2 次重试），
整文件重试至少间隔 30 秒，期间可处理其他文件；每个分片原有的 3 次尝试仍保留。
达到上限后保留原件，标记失败并继续其他文件；权限、授权、完整性错误不自动重试。
收到 HTTP 429 或百度 20012、31034、9013 后，整个上传队列等待 70 分钟。
限流不消耗文件尝试次数；到期试传，如仍限流，再等待 70 分钟。等待时间不是解封保证。
队列和等待截止时间保存在主程序 .state/upload_queue.json，重启后继续；不要手工编辑。
关闭程序不会自动唤醒，需保持主程序运行或到时重新打开。电脑休眠期间也不会上传。
重启后恢复的是文件队列，不是跨重启的分片断点续传；未完成文件可能重新上传。
“重试失败文件”可重置失败文件的尝试次数，但不会跳过限流等待。
Agent 的 status 输出含 queue：items（路径、状态、attempts、last_error、next_attempt_at）、
waiting_count、failed_count、cooldown_until、cooldown_remaining_seconds、cooldown_reason。
items 状态为 pending（排队/待重试）、uploading（正在处理）、failed（需人工处理）。
限流期间 accepting_archives=false，但仍会登记新拖入的文件；不要据此重复搬运文件。
上传 100% 不代表完成；只有完整回读校验成功并保存归档记录，才会释放原件。

## 云端索引备份与整项目恢复

每个云端项目目录内的“归档索引”保存独立 JSON 索引（格式版本 1），含项目名称/标识、
原始相对路径、云端路径/文件标识、大小、SHA-256、归档时间及修改时间。
索引不包含本机绝对路径或网盘授权令牌；文件名带内容 SHA-256，读取时会核对。
完整文件回读校验、本地索引保存、云端索引上传及回读核对全部成功后，才释放本地原件。
索引备份失败保留原件；相同路径、大小和哈希的后续尝试会复用已有云端文件并重新核对。
不要删除云端“归档索引”或手工修改索引。文件名中的哈希用于发现损坏，不是数字签名。

新电脑恢复：
1. 新电脑安装 Python 3.12，解压本工具源码后运行 setup.cmd，再运行 start.cmd。
   点击“网盘授权…”填写自己的百度应用 App Key 和 Secret Key，打开百度页面授权同一账号，
   将授权码粘贴回窗口并提交。无需原电脑的 projects.json 或 .云端记录，也无需旧 API 案例。
   账号凭据由 Windows DPAPI 加密保存在当前用户目录；换电脑需要重新授权。
2. 点击“从云端恢复整个项目…”，选择云端项目，再选择本地恢复父目录。
   文件恢复到该父目录下的项目子目录，按原相对路径还原，不需要先添加本地项目。
3. 每个文件下载后核对大小和 SHA-256。再次选择同一位置恢复，会重新核对已存在文件；
   内容一致则跳过，不同则使用带归档 ID 的后缀保存，绝不覆盖已有文件。
   同一路径的多个归档版本：较新的优先使用原名，其他版本保留后缀。
4. 普通网络失败每个恢复文件最多尝试 3 次；损坏索引、权限和校验错误会记录失败。
   遇限流停止本次整项目恢复；待恢复后再次选择同一项目和同一位置即可继续。
   关闭窗口会完成当前文件后停止整项目恢复；恢复目录不能位于任何正在监听的云空间内。
5. 结果会明确区分 complete / partial / stopped / rate_limited；只认 complete 为全部成功。
   恢复报告保存在程序 .state/recovery，包含成功文件、失败原因及实际保存路径。
   恢复范围仅包括已归档且有有效索引的文件，不包含未归档资料或空目录；压缩包按文件恢复，不自动解压。

既有索引补齐：点击“补齐选中项目的云端索引”，核对文件标识和大小后上传索引、回读核对。
重复执行可核对已有索引，不重复上传大文件。云端索引与数据都在同一网盘账号，不是异地第二副本。

Agent 无需接管桌面，也可用 CLI（这些联网命令需要先正常关闭 GUI，避免并发操作）：
  python cloud_space.py cloud-projects
  python cloud_space.py backup-indexes
  python cloud_space.py recover-project --remote "/项目云空间/具体项目目录" --destination "E:\找回项目"
用实际 Python 和脚本绝对路径替换示例。recover-project 的 destination 是最终项目目录。
stdout 输出 JSON，stderr 输出进度；退出码 0 表示完成，1 表示失败/部分完成。
上述命令需要网盘授权；status 仍是只读本地状态，不联网。
GUI 的 status.recovery 显示整项目恢复总数、完成数、失败数、状态及报告路径。
命令行恢复结果以退出码和最终 JSON/恢复报告为准，不以 GUI 心跳判断。
